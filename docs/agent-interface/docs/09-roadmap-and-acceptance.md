# 09 · 第一阶段产品隔离与可验证验收

## 事实边界

旧“现有招新平台增量 MVP、复用账号和数据库”方案已撤销。内部成员与招新筛选为独立产品；第一阶段在同仓 `member-platform/` 独立成员 server 与 infra，根 `server/` 仅考试。共同基线 `229e69c` 仍共 DB/账号/启动，不能以文档、API 命名空间或两个端口当成隔离完成证明。

代码存在、自动测试、本地 HTTP、真实浏览器、真实 Agent Host 与生产部署是不同证据。当前文档工作不执行应用测试，不继承旧布局通过数；历史事实见 [迁移记录](../../migration.md)。[04](04-api-and-workflows.md)固定成员 API，[运行手册](../../AGENT_INTERFACE_MVP.md)提供隔离布局命令。

## 第一阶段范围

1. 成员 server 与 CLI/MCP 位于 `member-platform/`，可独立安装/启动，不导入根考试应用；根考试应用不挂载组织路由、网页或初始化组织业务表。
2. 两套独立 DB、账号、会话/授权、配置和生命周期；成员业务不运行考试批次回收、上传暂存、转发或考生归档任务。
3. 成员本库 member/admin、逐请求授权、网页 Bearer 与短时 CLI grant、一次性 code、scope/资源 ACL 保持现有安全语义。不改变 `/api/v1` API 名，不做 OAuth/OIDC。
4. 项目目录/管理、知识检索、project-join schema、validate/持久草稿、可信网页确认与幂等提交、本人查询/补件/撤回和网页 admin review 保持已有成员能力；不是重新声称这些首次实现。
5. CLI 与本地 stdio MCP 同包同版本，显式成员服务根 `http://localhost:8902`，仅读取/准备草稿，不签发确认、最终提交或审核。
6. 提交可审查隔离 PR，完成标准测试与双服务合成数据验证。远端名/独立仓映射、部署与真实账号迁移不在本阶段执行。

## 双服务无模型端到端验收

1. 从新的两套空目录同时启动考试 8901 与成员 8902，确认每个进程实际 DB 路径不同，初始化不互相影响。
2. 分别建立合成账号：考试考生/管理、成员 member/admin 和另一成员；即使 ID 相同，密码/角色/会话不互通。跨服务 Bearer、CLI grant、角色升降与撤销均不能影响另一产品。
3. 用考试服务完成旧客户端登录/题目/提交回归；请求考试 `/org` 与组织 API 失败。成员服务不提供考试业务、也不触发归档/转发/批次回收。
4. 本人经成员网页授权 CLI，CLI/MCP 检索允许项目和来源明确的文档、validate/保存草稿；响应无确认 token。
5. 在可信成员网页读取本人草稿、核对并确认，提交得到稳定 ID；重试不产生第二条；另一成员不能读，CLI 与非 admin 不能审核。
6. 网页 admin 审核，本人查询；变更角色/撤销 grant 后重复请求被拒。不启动 LLM/Gitea/远程 MCP，业务仍可完成。

自动 HTTP 测试可以模拟确认接口，但不证明人类已看过内容；真实浏览器与 Host 必须另记，不能用协议子进程测试代替。
