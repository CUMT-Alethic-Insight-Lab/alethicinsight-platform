# 本地工作区保全与迁移清单

这是从 PR #3 历史人工清单修订的保全门禁，**不是已执行的工作区或真实数据迁移记录**。原方案把组织接口增量并入招新平台、保留根 `infra/`，现已撤销；历史事实见[迁移记录](migration.md)。当前纠正先在同仓 `member-platform/` 独立成员 server 与 infra，根 `server/` 仅考试，PR 审查后才决定独立仓与远端映射。`alethicinsight-platform` 历史误改名本次不纠名，不创建新仓 URL，不动原脏主仓、不读秘密、不部署、不迁移真实账号。以下方框均是操作前门禁，不是完成标记。

## 1. 先识别，不先搬家

- [ ] 分别确认 P: 与 E: 的仓库根、独立 `.git` 目录或 worktree `.git` 文件、分支、HEAD、remote 和工作树状态；不要凭文件夹名判断两个目录是同一仓库。
- [ ] 对每个明确的非敏感仓库位置，人工核对 `git status --short`、`git branch --show-current`、`git worktree list`、`git rev-parse --show-toplevel`。remote 核对在私有渠道进行，不把带凭据 URL 放入公开报告。
- [ ] `E:/projects/Aletheion` 仅作为历史来源登记，不升级成 monorepo，不递归搬入整个目录。
- [ ] `Alethic-Insight-Frontend-Templates` 完全排除，不编辑、不移动、不整理其内部文件。

## 2. 保全 P/E 两处未提交内容

- [ ] 在任何切换前登记两处 tracked 修改、未跟踪文件、被忽略但有价值的本地资料、嵌套仓库及未推送提交。`git status` 不覆盖全部 ignored 文件；不要运行会打印秘密正文的批量扫描。
- [ ] 对公开安全的代码修改保留补丁或本地提交，并保全未跟踪的代码素材；单个 Git 补丁不包含未跟踪文件，单个 commit 也不保全 ignored 数据。
- [ ] 真实凭据、数据库/WAL、上传、考试材料、会话、备份和运维日志仅在受限私有位置保全；不要临时 `git add -A`、提交到公共分支或上传云盘来“备份”。不读取或复制现有 CLI 凭据来完成接口演练。
- [ ] 如涉及正在写入的数据库，由获授权负责人使用一致性备份流程；不能把普通文件复制当作数据库一致性证明。当前文档任务不执行数据备份。
- [ ] 核对备份范围、数量/摘要、读取权限和恢复方式，确认原件仍完好后才继续；不得用 `reset --hard`、`clean` 或删除旧目录消除差异。

## 3. 区分 worktree 与独立 clone

| 类型 | 共享内容 | 迁移影响 |
|---|---|---|
| Git worktree | 共用主仓的对象库、refs 与 worktree 管理信息；各自工作目录/index/HEAD | 不是完整独立备份。直接拖动、复制或删除目录可能断开 `.git` 指向；主仓不可在未核验关联关系时移动/删除 |
| 独立 clone | 有自己的 `.git` 和对象库、工作目录 | 不共享本地未提交修改；普通 clone 通常也不包含另一个副本的未推送分支、未跟踪文件、ignored 数据或本地配置 |

- [ ] 如后续需要独立副本，先在新目标创建 clone，再通过已审核的提交/补丁恢复代码；单独保全不宜入 Git 的资料，不把复制 `.git` 关联文件当成新 clone。
- [ ] 如后续需要 worktree，由负责人使用 Git worktree 管理命令并核对共享主仓；现有 worktree 不自行挪位置。本次不执行 worktree move/remove/prune。
- [ ] 每个 coder 只操作分配的 worktree 与文件范围，按授权提交自己路径，不修改原脏主仓或推送。`feat/agent-interface-mvp` 仅是旧任务分支历史，不是当前隔离执行入口。

- [ ] 在新目标准备可回退的副本，保留来源，不使用剪切、覆盖或删除作为第一步。先确认空间、私有权限与排除项，不把真实数据复制到公开仓。
- [ ] 对非敏感源码核验提交历史/HEAD、文件差异、未提交内容恢复情况、依赖与本地链接；检查新路径的打包入口与版本一致性。
- [ ] 在隔离数据和新临时凭据目录中安装单包，验证 `alethicinsight-cli --help`、`alethicinsight-mcp --help`、项目标准测试，以及 loopback 合成数据 CLI/MCP 闭环；不沿用生产数据库或真实凭据。
